# Nue Vocabulary

*Internal working source for consistent Nue terminology in M5 information architecture, future docs, and contributor communication.*

This document expands the earlier template-focused terminology notes into a concise Nue-wide vocabulary. It is not meant to define every common programming or YAML term. Include a term here only when using it consistently prevents real ambiguity in Nue documentation.


## Core Principles

- Use **property** as the general data term in Nue.
- Use **key** when talking about YAML, JSON, or JavaScript object source syntax.
- Use **attribute** for markup syntax written on HTML or Markdown tags.
- Use **directive** for colon-prefixed Nue syntax such as `:if`, `:each`, `:is`, and `:bind`.
- Use **context property** for any named value available during template rendering.
- Use **data path** for dotted references to nested source/data structure, such as `meta.title` or `site.origin`.
- Avoid **namespace** for YAML/data grouping. It is not YAML terminology and is already overloaded by XML/SVG, CSS, and module terminology.

Preferred wording for YAML groupings:

- "the `meta:` group"
- "the `meta:` mapping" when exact YAML structure matters
- "keys under `meta:`"
- "the `meta.title` data path"

Example:

```yaml
meta:
  title: The UNIX of the Web
```

In YAML source, `meta` and `title` are keys. `meta:` is a group or mapping. `meta.title` is a data path. After Nue loads and merges the data, `title` is a context property available as `{ title }`.


## Data and Context

### Property

A named data value in Nue. Use this as the general term for data once it is considered part of Nue's data model or render context.

Use `property` for values visible to templates, values loaded from data files, generated page values, collection item fields, and values produced by data scripts.

### Context Property

Any property available in the template context during rendering.

Example: `title`, `description`, `url`, `dir`, `slug`, `headings`, `tagline`, or a helper function available to a template expression.

### Data Property

A property coming from a data source before or as part of context construction. Data sources include YAML, JSON, front matter, collections, parsed content, generated page metadata, and data manipulation scripts.

### User-Defined Data Property

A data property explicitly declared by the site author, usually in YAML, JSON, or front matter, rather than generated by Nue.

Prefer `user-defined data property` over `custom property`, unless quoting existing docs.

### Page Property

A context property specific to the current page. This includes front matter values and generated values such as `url`, `dir`, and `slug`.

### Component Property

A context property whose source is a component attribute at the call site. A component property is an input to the component.

Do not call every value visible inside a component a component property. A component can also use local properties, helper functions, and any inherited data Nue makes available to that construct.

### Local Property

A property created inside a template or component script for local use during rendering.

### Computed Data Property

A data property added or derived by a data manipulation script. Once merged into the template context, it is also a context property.

### Template Context

The final merged data object available while a template renders.

### Template Data

All source data that Nue loads or derives for rendering. This includes YAML and JSON data, front matter, collection items, parsed page data such as headings, generated page values such as `url`, `dir`, and `slug`, and values produced by data scripts.

### Data Cascade

The precedence order Nue uses when merging template data.

For current NueKit behavior, the broad model is:

1. Shared data from `@shared/data/*.yaml` and `@shared/data/*.json`
2. Root-level data, including non-configuration data from `site.yaml`
3. App-level data from relevant app folders and `app.yaml` files
4. Page front matter and generated page data


## Source Structure and Configuration

### Key

A source-level name in YAML, JSON, or JavaScript object syntax.

Use `key` when the source syntax matters:

```yaml
meta:
  title: The UNIX of the Web
```

Here, `meta` and `title` are YAML keys.

### Group

A friendly prose term for a source-level collection of related keys.

Use this for documentation aimed at readers who do not need exact YAML terminology: "the `meta:` group", "the `site:` group", "keys in the `collections:` group".

### Mapping

The precise YAML term for a key-value structure.

Use `mapping` only when exact YAML structure matters. In most Nue docs, `group` is easier to read.

### Data Path

A dotted way to refer to a nested key/property location, such as `meta.title`, `site.origin`, or `resources.models.users`.

Use `data path` when discussing where a value lives before or during merging. A data path is a documentation convention; it does not necessarily mean templates access the value with the same dotted expression.

Example: keys under `meta:` are flattened into the template context, so the `meta.title` data path becomes the `title` context property.

### Configuration

Settings that control Nue behavior rather than page/template content. Examples include `site`, `design`, `content`, `collections`, `sitemap`, `rss`, `server`, `resources`, `platform`, `include`, and `exclude`.

### Configuration File

A YAML file that Nue reads for framework behavior. `site.yaml` is the root site configuration file. `app.yaml` provides app-scoped configuration.

### Data File

A YAML or JSON file used as template data. For shared global data, use `@shared/data/*.yaml` or `@shared/data/*.json`.

Some files can be both configuration and data sources. `site.yaml` and `app.yaml` are the important examples: known configuration groups control Nue behavior, while other values can contribute template data.

### The `meta:` Group

The `meta:` group contains document/page metadata defaults. It is not limited to keys that become literal HTML `<meta>` elements.

Nue flattens keys under `meta:` into render data. For example, the `meta.title` data path becomes the `title` context property.

Current well-known examples include `title`, `title_template`, `description`, `favicon`, `og`, `og_image`, and `origin`.


## Markup and Templates

### Attribute

Markup syntax written on an HTML or Markdown tag.

Example:

```html
<a href="{ url }">{ title }</a>
```

Here, `href` is an attribute. Because its value is computed from an expression, it is also a dynamic attribute.

### Dynamic Attribute

An HTML attribute whose value is computed from a template expression.

Example: `href="{ post.url }"`.

### Directive

A colon-prefixed Nue template attribute with special semantics.

Examples: `:if`, `:else-if`, `:else`, `:each`, `:is`, `:bind`, `:onclick`.

### Control Directive

A directive that controls rendering flow, such as `:if`, `:else-if`, `:else`, `:each`, and `:is`.

### Event Directive

A directive that registers an event handler, such as `:onclick` or `:oninput`.

### Data Directive

A directive that passes data into a component without rendering that directive as a DOM attribute.

Examples include `:prop="expr"`, shorthand `:prop`, and `:bind="expr"`.

### Template Expression

A JavaScript expression evaluated against the template context.

### Escaped Expression

A template expression whose rendered output is HTML-escaped before insertion into the document.

Example: `{ title }`.

### Unescaped Expression

A template expression whose rendered output is inserted as HTML without escaping.

Example: `{{ markdown(excerpt) }}`.

### Template Syntax

The Nue-specific additions to standard HTML, including expressions, directives, dynamic attributes, loops, conditionals, components, and event handlers.


## Template Constructs

### HTML Template

A template written in HTML using Nue template syntax. Page templates, layout modules, and HTML components are HTML template types.

Long form: **Nue HTML template**.

### Page Template

A page-level HTML template that renders the page's own content. It is not a reusable component and does not fill a named layout slot.

### Layout Module

A reusable HTML template fragment that fills a named layout slot such as `header`, `aside`, `pagehead`, `beside`, or `footer`. Nue assembles layout modules around page content automatically.

### HTML Component

A reusable template unit referenced as a custom tag in HTML or Markdown.

### Client-Side Component

An HTML component marked for rendering in the browser instead of being rendered into the static HTML page at build time.

### Markdown Template

A template written in Nuemark syntax. Markdown pages and Markdown partials are Markdown template types.

### Markdown Page

A page-level Markdown template.

### Markdown Partial

A reusable Markdown template fragment included into another template or page.

### SVG Template

A template written in Nue SVG syntax containing SVG and optional embedded HTML converted to SVG during the build.


## Terms to Use Carefully

### Namespace

Avoid `namespace` as an official term for YAML or template data grouping.

Reasons:

- YAML does not use `namespace` for nested mappings.
- Web developers may read `namespace` as XML/SVG namespace, CSS namespace, module namespace, or global namespace.
- Nue already has clearer terms for the relevant concepts: `group`, `mapping`, `data path`, `configuration`, and `context property`.

Acceptable uses:

- True XML/SVG namespace discussions.
- Existing industry phrases such as "global namespace pollution" when that is the concept being discussed.

### Variable

Avoid `variable` as the general term for data visible in templates. Use `property` or `context property`.

Use `variable` only when referring to JavaScript variables in scripts or examples.

### Prop

Avoid `prop` in documentation prose unless quoting framework comparisons or existing code. Use `component property` for Nue component inputs.

### Custom Property

Avoid `custom property` for user-authored data because it conflicts with CSS custom properties. Prefer `user-defined data property`.


## Short House Style

- Property = data in Nue's render/data model
- Key = source syntax in YAML, JSON, or object literals
- Attribute = markup input syntax
- Directive = colon-prefixed Nue syntax
- Context property = any property visible during rendering
- Data property = property from YAML, JSON, front matter, collections, generated metadata, or data scripts
- Data path = dotted reference to where a value lives, such as `meta.title`
- Group = friendly term for related YAML keys, such as the `meta:` group
- Mapping = precise YAML term for key-value structure
- Avoid namespace for YAML/data grouping
